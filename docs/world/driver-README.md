# Miniature foreground driver

This headless driver owns one `MiniatureStore` and signs its opaque one-use challenges with existing owner-private keys. The strategic clock, authority frontier, pending intents, reservations and durable acknowledgements remain in that Store. Pure pacing emits hints only. There is no game, network, background launcher, key provisioning, role grant or wall-clock catch-up path.

The typed kernel and pure pacing passed independent R1 review before this composition began. Driver passed independent R2 after one combined repair of two R1 findings. The exact repaired39-file candidate passed author and independent native34-test/five-step gates. Full issue36 acceptance still requires the combined guarded Store/recovery/sync-fault and hosted checks; native game/transport behavior is outside this driver scope.

## Library

`Driver::create(CreateOptions)` requires the exact operator-pinned public membership bytes/digest, explicit scope/seed/three controllers/aggregate/provider IDs, an already admitted owner identity and possession of that identity's existing private key. The Store validates true genesis and controller/owner policy before creating its new profile2 database. Opening an existing database requires explicit scope and protected event/store/membership/authority minima; a missing key or failed private ACL is an error. Opening and status never claim authority, fabricate a replacement key or advance time.

`claim_authority` signs the Store-issued fresh greater-term/session claim. Persisted session labels cannot restore a reopened process's authority. `prepare_action` first queries the original RequestId/account/device/scope binding, validates operation/job/closed action/provider, and returns its original intent, expected revisions, binding and status. A changed retry is a conflict. A committed retry performs no authority claim or SQL write. Only a new request constructs a fresh revision map and signs a current Prepare challenge.

`configure_signer` selects existing keys for at most three actual genesis controller accounts using the Store's current identity/key/peer. One signer is retained per account. An identical selection is refused; a changed current identity replaces the old signer only after successful private loading. Immutable staged rotation keys are loaded through the accepted `PrivateVault::load_membership_keys` seam. Staging or choosing a file grants no role. Failed replacement retains the old signer; it still cannot pass current Store signature policy. Original pending actor/device identities are never rewritten.

`prepare_frontier` admits at most64 explicit actor requests. Every original RequestId is queried before its new intent is built; any already-bound request rejects the new frontier. Every actor must have an explicitly configured existing signer. The Store verifies current Economic proofs and the kernel determines canonical ordering, the first legal winner and its exact typed resource hold. Callers cannot supply reservations. Invalid earlier ownership candidates do not suppress the next legal candidate.

`advance_pending(true)` signs fresh current-tick Activity, settles the actual retained frontier against the actual Store world/authority, then signs Commit and returns only the real durable acknowledgement. `advance_empty(true)` prepares a genuine empty frontier before the same guarded path. `false` returns Inactive before effects. Expired, revoked, stale or mismatched activity/owner proofs remain Store failures. An accepted Activity is a local cooperative possession assertion, not native UI presence.

`resume_pending` requires every immutable original actor/device signer before issuing any Resume challenge, then reauthorizes the unchanged frontier under current policy. Missing or revoked keys pause work. `cancel_pending` is an explicit current-owner decision that records terminal cancellation, releases the hold and leaves WorldTick/resources unchanged. An old pending membership revision need not equal the new policy revision for cancellation.

`run_for(period_ms, duration_seconds, active)` accepts100..60000ms and1..60s. It opens a fresh process-local monotonic window, pauses immediately when inactive or when retained work needs an explicit decision, emits at most one outstanding pacing hint, and rearms from actual post-commit elapsed time. Missed slots are discarded. The private window is checked before/after proof work, before each Store mutation and again at actual Store `BeforeTransaction` and `BeforeCommit` cuts. An expired window can leave an authenticated Pending paused; it cannot admit a new advancing commit. That last Driver rejection cut precedes the Store's independent policy/crypto verification tail. Admitted synchronous verification/COMMIT/fsync may finish after the deadline and is never forcibly interrupted; the Store's own authentication expiry checks stay separate. `run_for_with_observer` exposes only the read-only `PendingPrepared` marker; callback time consumes the same window and cannot extend it. The deadline is cleared on every normal success/error return. `run_for` requires a separately claimed runtime. The explicitly named `run_as_owner`, used by CLI `--claim-authority yes`, starts the same budget before its fresh claim after initial file/vault opening. Inactive or retained-Pending runs pause before any claim. No saved wall time or caller clock hint authorizes a tick.

## Foreground CLI

Run `cargo run -p nf-world-driver -- --help` for the complete bounded flags. `create`, `status`, `step` and `run` are finite foreground operations. All open commands require an explicit database/scope and rollback minima. Mutation commands additionally require existing vault/save-root/account/device selection, `--claim-authority yes` and explicit `--active yes|no`. Ordinary peer/key identity is derived from guarded current membership, without a caller-selected peer fallback. `create` has separate explicit public trust-root flags.

`step` requires explicit128-bit request/operation/job IDs and one closed action: `colony:SITE:FACTION`, `build:MARKET:1|2`, `relationship:FACTION:OTHER:SCORE`, or `travel:FACTION:SYSTEM`. Entity ordinals identify immutable genesis entities, never request IDs. Existing committed retries return before a claim. Inactive steps and retained pending steps default to pause without a new claim. Exact retained bindings support explicit `--pending-policy resume|cancel|pause`; an unrelated or changed request cannot use that option to resume/cancel a frontier. The CLI configures one local signer; multi-actor resume requires the library's explicitly configured signers and otherwise fails closed rather than changing the actor set. `run` pauses on retained pending work. A successor owner or a rotated/revoked original device may be unable to query the old actor/device binding through singleton Step. Such current-owner recovery uses the named library `Driver::cancel_pending`; the CLI does not relabel an immutable retry or promise successor cancellation.

Output is a bounded public snapshot summary (scope, tick, sequence, store/member/authority frontiers, pending marker/count and state hash). Errors contain finite classifications. Keys, proof signatures, raw arguments and private paths are never printed. Non-Unicode command arguments are refused without an input-bearing panic. The driver creates no game/save files and does not spawn a node, network or game process. Existing private ACL helpers are owned by the accepted vault shell.

Disposable tests create and resolve their intended parent even in a fresh checkout. Cleanup uses privately captured original canonical ownership, verifies strict containment immediately before recursive removal, and ignores any later mutation of the public convenience path.
