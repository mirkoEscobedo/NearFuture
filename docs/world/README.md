# NF-MINI-1 pure core

Phase1 implements only `nf-world`: a bounded no_std value model and pure rules. [Proposal](proposal.md) records the scope and [exact phase2 contract](integration-contract.md) records the proposed later kernel/store/driver integration; typed kernel implementation is now frozen for independent review; atomic Store/driver composition remains pending. Issue36 remains open pending actual atomic persistence, authority/activity policy, pacing/restart and reviewed headless composition.

Genesis has three systems, three account-controlled factions, six fixed sites (three initial colonies), three abstract fleets and three symmetric pair relations. Integer NF resources and costs are fixed in `RULESET_CONFIG`; `ruleset_hash()` commits its exact bytes. These are Near Future rules, with no native/Nex compatibility claim. No function reads a clock, identity vault, membership database, filesystem, network, ambient random generator or game object.

`generate(Genesis)` returns private validated State; immutable typed views expose public facts. `evaluate(state,committing_tick,candidate)` validates control, revision, sites/routes, locks and resources, returning a privately constructed immutable ActionPlan/ResourceHold. These objects certify pure model policy only, not membership, cryptography or runtime authority. Candidate/device/proof authentication and request deduplication belong to the approved future owner. A raw component or retained hash alone authorizes nothing.

`apply_plan(state,actual_committing_tick,plan)` requires exact input State and exact plan tick before mutation. State does not carry a second WorldTick; an empty tick can leave component bytes unchanged, so tick equality is required even with equal component bytes. An action committing at N creates construction due N+2 and travel due N+3 using checked additions. The supplied N is the resulting commit tick, not N-1 or local campaign time.

`plan_reservations` accepts up to64 already trusted-admitted candidate values, rejects duplicate request/operation/job identities, sorts by `(target_entity,operation,job)` under the sole miniature provider, and selects only the first legal winner. Relationship targets are their symmetric pair entity, not the initiating faction. An invalid pair sorts by its initiating faction ID but always fails reference admission. Invalid earlier candidates hold no resources. Every further legal candidate conflicts. Only the returned winner owns a ResourceHold; callers cannot construct or alter holds. A zero-cost relationship returns a zero hold and needs no durable resource row. The later Store must reproduce this plan instead of accepting caller-chosen reservations.

`due_events(state,tick)` returns the complete due schedule list in `(due,id)` order, rejecting overdue unprocessed schedules. `apply_due` requires exact full recorded events: missing/reordered/duplicate/altered events cannot silently complete a different timer. It removes each schedule and increments aggregate revision once per event. Player actions use the start-of-tick view; the future kernel applies the action then all due events before final validation/hash/commit. An intermediate action result may still contain old events due at the current tick and must not be persisted as a final snapshot. Empty event reduction is a value-level no-op; it does not itself advance a strategic clock.

`validate_at` checks canonical identity/order/counts, fixed topology/ownership, pair bounds, schedule/phase bidirectional references and resource accounting. At trusted committed N, every pending construction has remaining duration1..2 ticks and arrival1..3. Internal action-output validation instead uses actual committing N and permits old due==N only until exact due reduction; it is not final snapshot admission. Remaining distance is checked by subtraction, so high ticks do not overflow a computed upper bound. Available plus spent resources equal genesis totals. Spent credits exactly match newly founded colonies and purchased industry slots; supplies cover those costs plus integral20-unit travel expenditure. This validates model consistency, not the authenticity of an arbitrary snapshot or its history. Only accepted journal replay/authenticated ownership can establish that provenance.

The component codec is [domain7/schema2/type5](component-schema.md). Foundation and accepted kernel schema1 decoders remain unchanged and reject these bytes. No schema or capability is registered on public IPC, Java or transport.
