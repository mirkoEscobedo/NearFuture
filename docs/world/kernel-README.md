# Typed miniature kernel checkpoint

The new `nf_kernel::miniature` module implements the private NF-MINI-1 domain7/schema2 records and pure transitions. Independent R1 source review passed with no Important findings; the isolated aggregate and publication gates remain separate. Existing schema1 kernel APIs and bytes remain closed and unchanged; the only accepted-source edit is an additive module export. Store/driver implementation, authenticated authority/activity, atomic durable commits, restart recovery and whole issue36 acceptance remain pending.

The [integration contract](integration-contract.md) defines exact ordered Snapshot1, Batch2, Frontier3 and Intent4 fields. Their nested Component5 is delegated to the reviewed nf-world contextual decoder. Public input records are bounded to1MiB; components128KiB; frontiers/batch intents64; due timers32; retained outcomes4096; cumulative nested entries16384. Counts and lengths are checked before allocation. Headers, closed tags, expected-revision map order, presence bytes and trailing bytes are strict. Snapshot consistency requires provider revision equal to WorldTick, EventSeq at least WorldTick and component revision at most tick.saturating_mul(33). These are reachable-shape checks, not authenticated-history evidence.

`MiniatureWorld::new(metadata,component)` returns an immutable validated value. `admit_miniature` checks exact scope/provider/aggregate identities, duplicate request/operation/job identities, retained outcomes, checked tick/event advancement and capacity, then invokes the NF-world canonical planner. Only its first legal winner supplies a private derived hold. A stale provider revision is a finite rejection and does not suppress the next legal candidate. A relationship records its exact zero cost without a positive frontier hold.

`settle_miniature` requires the exact source World, term and session of its frontier. It applies the selected action at actual N, then the complete due set at N, advances the sole tick/provider revision once and appends terminal outcomes with one EventSeq increment. `cancel_miniature(world,frontier,current_authority,current_membership_revision,reason)` accepts only Cancelled/AdmissionChanged and checked nonregressing pure context, records unchanged immutable intents, advances EventSeq once and preserves tick/component/provider revisions without action or due events. These supplied pure context labels establish no cryptographic authorization; the approved future Store must authenticate fresh issued proof contexts against SQL state.

`replay_miniature` rederives the full deterministic transition from trusted source and recorded intents. It checks every recorded action, exact cost, created timer, due tuple, outcome and hash. `decode_miniature_batch(bytes,&trusted_before)` performs that complete correspondence check before exposing a private batch; a matching before hash alone is insufficient. No replay function calls an ambient provider, RNG, clock, repository or game API. A serialized checkpoint and replay test is value-level recovery evidence; actual SQLite/crash recovery is still unimplemented.

`miniature_request_binding` uses the maintained NF-CANON RequestBinding helper with private operation kind4 and SHA256(exact Intent4). Device ownership, action, scope and expected revisions are immutable; membership/authority/tick/proof are fresh admission context outside that digest. This does not register kind4 on public foundation IPC/wire or transport.

`MINIATURE_IMPLEMENTATION_HASH` is the one compiled closed-profile source identity. Constructor/replay have no caller-selectable implementation/hash field; their implicit registry admits only this compiled profile. `tools/generate-miniature-source.cjs --check` recursively inventories every Rust production file under nf-kernel/src/miniature and nf-world/src, including profile.rs. Only `miniature/generated_pin.rs`, containing one generated fixed byte literal/export and no logic, is excluded from its own hash. UTF-8 CRLF is normalized to LF; no other rewriting occurs. The domain-separated binary inventory is `NF-MINIATURE-SOURCE-1` plus NUL followed by lexically sorted path-length u32LE, path UTF-8, content-length u64LE and raw content SHA256 tuples. New production paths therefore change the pin. The [inventory](../../crates/nf-kernel/tests/fixtures/miniature/source-bundle.json) contains26 files with bundle digest `9261c94ec6e936e9c14c0af0ac7984dfd5fa1de59cf26b7fd6deb80c2fcbe5f6`. This identifies owned source, without compiled-binary or game equivalence claims. The future Store compares its fixed profile identity to this constant during create/open/replay admission.
