# NF-032 / issue #36: canonical miniature World proposal

Status: documentation-only implementation proposal. No new World crate, shared manifest, accepted kernel/store/identity source, schema registration, database, authority process or game installation is changed by this document. Issue #36 can be verified headlessly after the additive integration below is reviewed. These are explicitly Near Future rules, with no Nex/Starsector numerical, economy, flight or native-gate claim.

## Ownership and dependency proposal

Create `crates/nf-world` as `#![no_std]` plus `alloc`, workspace unsafe forbidden, depending only on path-local `nf-contract` and exact `sha2=0.10.9` with default features disabled. It owns immutable validated miniature state, deterministic generation, closed commands/events, read/write access plans, integer rules, schedule reduction and typed component codec. No SQL, filesystem, clock, entropy, identity keys, network or game imports belong in it.

Create `crates/nf-world-driver` as the owned imperative composition, depending on path-local `nf-world`, `nf-kernel`, `nf-store`, `nf-identity`, `nf-contract`, existing exact `getrandom=0.4.3` and `zeroize=1.9.0`. Use standard-library pacing and the accepted private vault; no new third-party effect dependency is proposed. It owns one Store writer, one foreground command loop, current membership/proof admission, authority lifecycle, bounded pacing input and CLI. Tests generate disposable identities/private directories. No secret, executable game content or production operational role is committed.

The current accepted kernel only registers `SeekPeace`, `AdjustRelation`, `AdjustMarket` and two events per successful job. Its Store only reserves a negative market-credit adjustment. Colony/industry/fleet state cannot safely fit those APIs. Explicit coordinator approval is required for the narrow typed changes described here to `nf-kernel` and `nf-store`; there is no probe payload, arbitrary provider blob, sidecar database or second strategic writer. Transport authors retain the existing identity/membership/retained-query API behavior.

Root owns shared Cargo/lock/architecture/CLI wiring and assigned integration authorship. Initial author scope is the two new crates, their tests and `docs/world/**`; accepted-module changes receive separate ownership before implementation.

## Exact miniature ruleset NF-MINI-1

Genesis takes explicit UniverseId, HistoryId, 32-byte seed and three admitted account IDs. Ruleset identity is SHA256 of one versioned fixed canonical configuration. IDs derive deterministically from domain-separated SHA256 of scope, seed, entity kind and ordinal, taking exactly16 bytes and rejecting collisions. Hashing is not entropy or authentication. Topology is fixed; the seed never selects an ambient RNG stream.

Generate exactly three systems, three factions, six markets and three abstract fleets. Names are fixed UI labels outside authoritative rules; canonical records contain IDs and closed numeric enums. Systems form the directed symmetric ring A-B-C-A. Each edge has travel duration3 ticks and cost20 NF supplies. Each system has two immutable market sites: site0 begins as its faction's colony, site1 begins unclaimed. Each faction has one immutable controlling account, a treasury of200 NF credits and100 NF supplies, one fleet docked at its starting colony, and neutral relations with the other two factions. Fleets are abstract strategic tokens, not player flight or native combat fleets.

One WorldTick represents one NF strategic hour. Proposed pacing manifest default is1000 milliseconds per logical tick, bounded100..60000. This does not convert Starsector time. All resources are checked unsigned u64 integers; relationship score is signed integer basis points in [-10000,10000]. There is no floating-point authoritative arithmetic. Fixed genesis has no income, stochastic market growth, combat, salvage, minting or offline economy.

Supported intents:

| Intent | Authorization and preconditions | Cost and effect |
| --- | --- | --- |
| CreateColony(site,faction) | Current PLAYER controls faction; unclaimed known site in faction's starting system; fleet docked there; exact revisions | Reserve then debit100 credits/40 supplies; site becomes that faction's colony immediately |
| BuildIndustry(market,kind) | Current PLAYER controls owning faction; colony exists; kind is Farming1 or Workshop2; absent and not constructing; exact revisions | Reserve then debit60 credits/20 supplies; construction locks that slot and completes after2 logical ticks |
| SetRelationship(other_faction,score) | Current PLAYER controls initiator; distinct known faction; exact shared pair revision; score bounded | Set symmetric NF relationship; no implied Nex diplomacy or native reputation; no resource cost |
| Travel(fleet,destination_system) | Current PLAYER controls fleet faction; docked; destination is direct route neighbor; exact revisions | Reserve then debit20 supplies; departure committed now, arrival after3 logical ticks; fleet locked in transit |

Every request includes the accepted typed RequestId/OperationId/JobId/account/device/scope binding, expected revisions and exact canonical action bytes. Ownership mismatch, stale revision, insufficient spendable resources, transit/construction locks, unknown IDs/kinds, wrong scope/ruleset, overflow and unsupported versions produce finite closed rejection tags. No field is silently dropped.

For this miniature prototype, every user action writes the single miniature aggregate and one dedicated miniature provider-state aggregate. The conservative rule is at most one successful player intent per tick; conflicting simultaneous intents are sorted by the existing kernel tuple `(provider,target_entity,operation,job)`, never worker arrival or filesystem order. The first legal action succeeds and the other competing valid actions receive Conflict. An earlier invalid action reserves nothing and does not suppress the next legal action. This intentionally sacrifices throughput and makes both ownership and treasury double-spend outcomes explicit. Expanding independent aggregate concurrency is a later versioned rule change.

Reservations distinguish available from pending-held credits/supplies. Pending costs remain held across a crash; they are neither spendable nor charged twice. Commit atomically converts the winning hold into consumed cost and clears losing holds. A cancelled/rejected pending action atomically releases its hold. Existing schema1 reservation semantics remain unchanged.

## Pure state and schedules

Proposed immutable State contains: topology system tuples and routes; faction tuples with controlling account, treasury credits/supplies; six market tuples with system/site index and optional owner; bounded industry slots; three fleet tuples with faction and docked/in-transit discriminated location; shared pair relations; schedules; an aggregate revision. Scope/seed/ruleset and the authoritative WorldTick remain the existing kernel fields, not a second counter in the component.

Industry slot is either Absent, Constructing(schedule ID), or Complete. Fleet location is Docked(system ID) or InTransit(schedule ID,origin,destination). Schedules contain deterministic ID, creating operation ID, due WorldTick, closed kind, subject ID, exact expected subject phase and committed completion payload. IDs derive from creating operation plus event ordinal. No arbitrary callback, script, class path or recurrence is stored.

Schedules sort by `(due_tick,schedule_id)` and are bounded32 total, with max2 industries per market and one travel per fleet. Snapshot validation checks every reference, no duplicate relation pair/ID, exact three/three/six/three counts, route symmetry, treasury bounds, phase/schedule bidirectional references and a due tick strictly later than current committed tick. Creating a schedule uses checked tick addition from the committing batch tick: an action committing at tickN completes construction at N+2 or travel at N+3. The start-of-tick input is tickN-1; using it as the departure time would shorten the declared duration and must reject. Due events execute once at the end of an advancing batch, before its final state hash; player actions use the start-of-tick snapshot. An arrival/completion at tickN therefore becomes available for player actions at tickN+1. Removed schedules are absent in the committed snapshot; replay applies the recorded completion and never resamples or invokes a provider.

If two due events touch the same subject or a schedule's expected phase does not match, reject the complete candidate batch and pause. Do not skip a malformed timer or partially publish a tick. With NF-MINI-1 each subject has at most one pending timer and this invariant is checked on both encode/decode. No rules currently draw randomness after genesis. Future stochastic event choices must be recorded in events with explicit scoped RNG audit; a seed alone is not replay evidence.

Proposed pure APIs: `generate(Genesis)->Result<State,WorldError>`, `validate(&State,WorldTick)`, `evaluate(&State,WorldTick,&WorldAction)->Result<ActionPlan,WorldError>`, `apply_action(&State,&ActionEvent)`, `due_events(&State,next_tick)`, `apply_due(&State,&[ScheduleEvent],next_tick)`, plus strict typed component encode/decode. ActionPlan contains exact typed access sets, two-resource reservation and deterministic action event; fields exposing authorization are data-only until the driver/kernel validates them. Constructors keep validated State mutation private.

## Typed kernel domain7 schema2

Keep existing domain7/schema1 snapshots, intents, frontiers, batches and their exact bytes unchanged. Preserve `WorldSpec` and its existing constructors; add an explicit miniature constructor carrying a typed component, with an accessor returning an immutable optional miniature view. A prototype kernel World has empty legacy faction/relation/market collections and one owned miniature provider; miniature facts exist once, in the new component. Legacy data is not a competing mirror.

Schema2 explicitly registers Snapshot1, Batch2, Frontier3, Intent4 and MiniatureComponent5 in private kernel domain7. The same NF-CANON-1 fixed header, LE widths, typed IDs, ordered collections, strict presence/enum checks and SHA256 policy apply. Type5 is a closed typed record implemented by nf-world; it is not opaque provider storage. Schema2 Snapshot includes legacy fixed fields and a required fully decoded type5 component. New command/event tags and Miniature provider kind/domain/capability are legal only under schema2. Unknown schema or command tags fail closed. Foundation generic and Java/wire registries continue rejecting this private domain; no public capability is promoted.

Proposed schema2 Intent extends the accepted request/operation/job/actor/scope/provider/expected-revision fields with exact device and admitted membership frontier, then typed WorldAction. Signed driver challenge binds the full intent digest, proposed authority term/session, scope/ruleset, next logical tick and fresh one-use nonce. A retained retry with changed action, device or frontier must follow the documented binding policy and never silently become a new action under the same RequestId.

Schema2 Batch adds explicit disposition AdvanceTick or CancelPending. AdvanceTick changes tick by exactly1 and event sequence by exactly1, including empty active-player ticks. It contains accepted action events in canonical job order followed by exact due schedule events. CancelPending retains tick and advances event sequence exactly1, records terminal finite rejections and reservation release, and cannot include resource, ownership, movement or schedule effects. It is used when pending admission is invalidated by membership changes. Old schema1 always retains its current tick+1 semantics and exactly-two-events replay check. Schema2 replay checks the closed action-to-event correspondence, recorded rejection reasons, timer correspondence and after hash without any live clock/provider/entropy.

Component byte ceiling128KiB; full snapshot/frontier/batch ceiling remains1MiB, nested component128KiB, frontier64 intents, schedules32, industries12 and fleets3. Count/length checks precede allocation; noncanonical orders, duplicate IDs, trailing bytes, unknown component/ruleset versions and invalid aggregate revisions reject. A component with its declared ruleset hash but incompatible constants is Unsupported, not a best-effort load.

## Store profile2: one transaction and no forced migration

Add explicit prototype `Store::create_miniature(...)` and exact profile2 opening. Accepted Store::create/schema1 histories remain profile1; opening an old DB uses the verified profile1 definitions and codecs unchanged. Do not change user_version on an existing database, silently regenerate genesis, or migrate accepted histories just to run this prototype. Unknown profiles preserve bytes and fail closed. A later migration requires its own reviewed public contract and backup evidence.

Profile2 retains existing rollback-journal/synchronous-EXTRA/private local-disk requirements and the sole Store connection. Add typed world reservations (operation, source faction, credits, supplies), authority/time metadata and journal dispositions; the complete schema2 kernel World includes schedules. No second connection, SQLite path exposed to another writer, sidecar state or separate commit of component bytes is allowed. Existing membership codec/table and public repository/query seams remain exact; prototype-specific changes are explicitly version-dispatched.

Profile2 adds `WorldKnownFrontiers { storage: KnownFrontiers, minimum_authority_term: AuthorityTerm }`; reopen verifies both the accepted storage/membership minima and the separately retained authority minimum. The host protects those public minima outside a replaced backup, as with the existing profile. A raw old backup cannot establish a newer authority term merely by starting a process.

Prototype APIs proposed for review: `claim_world_authority(expected_term,owner_account,owner_device,new_session)` commits a checked monotonically increased term and exact active session under the exclusive Store writer; `prepare_world(frontier,device_bindings,expected_membership,typed_reservations)` validates current durable membership and deterministic reservation plan in the transaction; `commit_world(batch,authority,expected_membership)` checks current persisted term/session, tick/event frontier and membership, then commits World, schedules, resource holds/consumption, request outcomes and outbox atomically; `cancel_world_pending(...)` records schema2 CancelPending against current durable policy and frees holds; `resume_world_pending(...)` only rebinds the unchanged exact frontier/reservations to a newly claimed session after fresh policy admission. Names may settle during approved implementation; their atomicity and checks are the required seam, not an existing API claim.

Authority metadata contains term, current RuntimeSession, admitted authority account/device and paused/running policy disposition. It has no independent strategic tick. Claim checks current active device and existing AUTHORITY_CANDIDATE role; this role merely permits explicitly configured local authority ownership and is not a quorum/election certificate. Member economic admission uses current PLAYER plus existing device proof/peer binding. Identity changes are serialized by the same owner; commit must compare the actual membership revision inside its SQL transaction. If it changed, pause and cancel/re-admit the pending work according to its exact current policy, without rerolling, charging or advancing a tick. Revocation cannot be delayed behind automatic strategic continuation.

Prepare durably writes the exact pending frontier and deterministic winning reservations before Accepted. Commit returns only the existing private DurableAck after SQLite commit; no response, tick, UI spendable balance or outbox delivery is published first. Preserve BeforeTransaction/AfterWrites/BeforeCommit/AfterCommit/BeforeAcknowledgement fault cuts. Uncertain commit quarantines the owner; reopen/query determines the retained result. Bounded DB/request/outbox limits remain explicit backpressure, never an automatic new history. Reading tick/hash or CLI status performs no advancement.

## Authority, active-player policy and pacing

One local foreground owner is the initial authority. There is no network election, quorum claim, automatic takeover on timeout or concurrently advancing replica. A second Store writer fails on the existing exclusive lock. Restart explicitly claims a greater persisted authority term and fresh runtime session; old-session frontier/result/commit requests fail before mutation. A recovered valid pending frontier may be deterministically re-evaluated under its rebound session; no wall-clock gap turns into extra ticks. An already committed request is queried before any new prepare.

The cooperative policy advances only with a healthy writable authority, admitted supported ruleset/component, complete required input and at least one fresh authenticated active PLAYER lease. Lease challenges bind account/device/scope/actual peer, proposed tick, authority term/session, membership frontier and fresh nonce using existing DeviceProof. Leases are bounded64, refreshed explicitly and expire after30 seconds of monotonic runtime time. They are ephemeral and are all cleared on restart. The CLI never creates operational roles as a side effect of starting the loop; genesis provisioning of disposable test identities is a separate explicit test command. Presence is a cooperative liveness assertion, not proof of honest gameplay.

Wall-clock UTC timestamps, local campaign clock, package publication/original-campaign dates and CLI display times never enter authoritative transition arithmetic. The process may use monotonic Instant to pace one proposal at a time. When idle, blocked, suspended or overdue it discards missed pacing slots. After any commit or return from pause it sets the next pacing deadline to now+period; it does not loop over elapsed periods. UTC backward/forward jumps cannot alter tick or timer contents. For reproducible tests the owner consumes a supplied elapsed/pacing observation; the pure core has no clock port.

All absent/stale players, missing jobs, unavailable membership, storage error/quarantine, invalid schedules, capacity exhaustion or authority mismatch cause strategic pause. One participant entering a local menu/combat does not pause a different active participant. On restart there are zero active leases: first status shows the exact stored tick and schedules, and no tick advances until explicit authenticated activity. This is the initial no-offline-catch-up NF policy.

## CLI and public evidence plan

New foreground CLI `nf-world-node` has explicit `create`, `status`, `step`, and bounded `run --duration-seconds 1..60` commands with explicit DB, private vault, scope/ruleset/config and retained known-frontier inputs. `create` refuses overwrite. `status` opens existing state and prints only public bounded tick/hash/pause/revision/schedule counts. `step` requires authenticated activity and intents, advances at most one tick and returns only a durable status. `run` uses exactly the same driver and accepts finite typed commands over a bounded local input seam; it does not use transport or a live game. Secret seeds/tokens/proofs are never diagnostics. A test-only scenario executable can create generated disposable identities and scripted challenges; ordinary commands cannot default to fabricated authorization.

Before code, approve typed integration ownership and exact schema/store profile. Then follow public vertical RED/GREEN rather than counting missing targets or setup errors as behavior RED:

1. Real generated genesis through the public driver fails its required three/three/six/three counts and stable typed snapshot hash while stub behavior exists; implement generation and strict round-trip/reference validation. Preserve schema1 golden bytes/tests unchanged.
2. Two differently ordered colony claims and two same-treasury builds yield the same one accepted legal outcome, same finite conflict outcome, one cost and one schedule. Repeat every permutation/completion order for finite small frontiers; stale/unauthorized/unknown/overflow cases hold no resource. Use meaningful independent invariants and expected arithmetic, not implementation-mirroring assertions.
3. Empty active tick, absent/stale player, missing authority/input, UTC discontinuity and a long pacing gap produce exact tick counts. A five-minute simulated stop advances zero ticks; resumed loop advances at most one due proposal and schedules future pacing without catch-up.
4. Commit construction/departure, snapshot actual SQLite, close/reopen with retained minima and compare immutable state/schedules/hash. Advance to exact arrival/completion ticks, replay recorded batches into genesis and compare byte-identical snapshot; replay never calls RNG/provider/clock. Repeat restart before/at/after due tick and retry original RequestId to prove no duplicate schedule/effect/resource charge.
5. Actual two-owner opening fails; authority restart increments persisted term and rejects stale session results/commits. Membership revoke/change between prepare and commit prevents the old intent and releases holds only through durable cancel; backup below known world/authority/membership minima rejects. No independent second clock continues during any failure.
6. Owned-child crash cuts around prepare, commit and acknowledgement plus a real SQLite quota failure preserve pending versus committed state and no premature DurableAck. Reuse native supervised Job Object process ownership on Windows and finite exact-child cleanup on all platforms; retain the already required Linux real-sync-fault lane for new profile transactions. Stubs of crypto or SQLite are not acceptance evidence.
7. Strict limits/canonical malformed corpus and schema1 regression gates; workspace fmt/Clippy/types/boundaries, headless commands and isolated release build. Independent review allows at most two semantic repair rounds. Link exact revision/ruleset hash/commands/results and hosted OS evidence before closing36.

The headless miniature can satisfy36 without native Starsector binaries. Full Game G5, native materialization, promoted-field writer coverage, visibility-filtered remote snapshots, transport-driven mutations/consensus, huge-save import, tactics and full Nex economy remain separate gates. Its small accepted World must not be called an authority over an existing local campaign.
