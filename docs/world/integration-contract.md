## Immutable intent and fresh admission

Immutable type4 binds device ownership, action, scope and expected revisions; it excludes policy frontier, authority/session, committing tick and proof. Use existing canonical RequestBinding helper with operation_kind4 and payload_digest=SHA256(exact type4). Changing action/device/expected revisions/scope under RequestId conflicts. This private profile use does not widen foundation generic operation admission.

A Pending frontier has not advanced source tick/revisions. Restart can freshly authorize that unchanged intent under current authority/membership, preserving its bytes/digest. Old envelope/proof becomes invalid. Source-state change or invalidated actor/device/role requires durable CancelPending, and a new RequestId for changed action. Resume never rewrites an old bound frontier field inside the intent.

Every lease/claim/prepare/resume/cancel/commit uses an OS-random32 one-use nonce. SHA256 challenge transcript: ASCII NF-MINI-AUTH-1+NUL,purpose1,universe16,history16,ruleset32,current_term8,proposed_term8,current_or_proposed_session8,decision_tick8,current_membership_revision8,actor16,device16,binding_digest32,challenge_sequence8,nonce32. Purpose1 Lease/2 Claim/3 Prepare/4 Resume/5 Cancel/6 Bootstrap/7 Commit. Lease/Claim binding_digest is exactly zero32; Prepare/Resume bind the unchanged exact type4 digest; Cancel/Commit bind SHA256(exact current retained type3 frontier); Bootstrap binding is defined below. Lease/Claim/Prepare/Resume/Commit decision_tick is actual world.tick.checked_next(); Cancel uses actual world.tick without advancing it; Bootstrap uses0. Only Claim changes proposed_term to current.checked_next(); normal purposes require proposed_term=current. Bootstrap uses both terms0 and no authority/session claim. Fresh session is nonzero/different from prior session; term supplies the monotone fence. Current context and pending digest come from actual loaded state, never caller labels. DeviceProof signs its accepted closed scope/account/device/peer/challenge/frontier using maintained Ed25519.

MiniatureStore owns private AuthRuntime with a checked-increasing challenge_sequence and bounded64 outstanding challenges. Public issue_challenge(purpose,bound_intent_or_pending_reference) derives exact context from loaded world/authority/membership, allocates OS nonce, stores issued_at/deadline as std::Instant and returns public challenge plus opaque ticket. The ticket has no public constructor; it grants no authorization by itself. Sequence overflow fails closed. Registry stores exact purpose/context/binding/peer/nonce/sequence and never trusts values decoded back from a ticket. Tickets can be presented at most once: remove the exact registry entry on first proof attempt before any signature/policy validation, then reject expired/wrong-purpose/wrong-binding/stale-state requests. A failed validation or SQL rollback does not restore that ticket; retry requires a newly issued challenge and new signature. Sequence is in the signed transcript, so even accidental random nonce reuse cannot repeat a challenge within a session. Every create/open starts with a private claimed_in_this_runtime=false guard; only a successful fresh purpose2 claim of the checked-greater persisted term sets it. Before that, retained status/query and explicit authority-claim challenge are available, but Lease/Prepare/Resume/Commit/Cancel issuance and strategic mutation refuse, so reopening cannot reuse a persisted session without new claim. Restart, authority change and membership mutation clear outstanding challenges/leases; old session/term transcripts cannot be reissued. Capacity rejects rather than evicting a live ticket. No bounded registry is an unbounded cache of consumed secret values.

Production freshness comes from Store-owned std::Instant observations; there is no public caller-supplied elapsed/now/activity value. The pure pacing policy may consume supplied observations in unit tests, but ordinary SQL mutation cannot use that pure input as authentication. Challenge/lease lifetime is bounded1..30s by explicit local configuration; expiry is checked before admission and again at the final admissibility cut before COMMIT. Public tests use actual short-lived issued contexts and real crypto/SQL to demonstrate expiry and first-attempt consumption; no fake clock or crypto grants production authorization.

Peer must already be authenticated. The headless local signer is the configured private-vault device whose public identity/peer matches durable membership; there is no network-peer authentication claim or arbitrary CLI peer-string fallback. Inside the transaction, MembershipState::authorize verifies current exact proof.frontier, scope/account/device/key/peer/challenge and nonrevoked PLAYER for economic/lease admission. Lease actor must be one of the three controlling accounts. The authority additionally requires AUTHORITY_CANDIDATE on that authenticated PLAYER account. This explicit miniature policy reuses accepted Economic authorization plus current role checks; no identity schema/operation extension is needed. Startup grants neither role.

accept_activity(ticket,DeviceProof) consumes a Lease-purpose ticket, verifies its current SQL context/signature/policy and records an ephemeral private ActivityLease holding original proof, issued context, exact decision_tick and monotonic deadline. At final AdvanceTick admission the Store must find at least one such lease for the actual N/current term/session/membership, check its live deadline and reverify the original DeviceProof against current transaction membership and its stored transcript. A lease for N never authorizes N+1 even if its30s deadline remains. Successful AdvanceTick consumes/invalidates every N lease; further ticks need fresh explicitly asserted activity and new proof. A failed commit cannot reuse a consumed commit challenge; retry obtains a new purpose-bound owner proof and uses only a still-live current-N activity lease. Run is an explicit cooperative activity assertion, allowing the configured local signer to renew only while that foreground assertion is active; it is no evidence of native menus/combat/presence.

Prepare/resume require fresh purpose-matched proof per original actor/device; Claim has its own proof. AdvanceTick commit additionally consumes a fresh purpose7 Commit authority fence, separate from Claim/Prepare/Resume and bound to the current pending frontier, with decision_tick=N and binding_digest=SHA256(exact current pending type3). Empty tick first prepares an explicit empty frontier, so it has the same signed owner/pending/tick fence. Cancel uses purpose5, current nonadvancing tick and exact pending digest, and cannot accept Lease/Commit/old economic proof. Driver passes opaque ticket plus original proof; SQL rebuilds expected context from actual state and compares every bound field. Commit verifies admission membership==current membership and current owner device/roles. Changed policy pauses and requires complete fresh resume or durable cancel. A private wrapper token alone never proves signature, current policy, expiry or activity.

The final admissibility cut occurs after all checked writes and after any BeforeCommit fault/test hook, immediately before invoking SQLite COMMIT. It rechecks Store-owned monotonic deadlines, exact pending/tick/authority and current transaction membership, including active lease and owner proof. Expired activity while queued or during transaction rolls back without tick/ack. Expiry after this decision cut does not retroactively revoke an in-progress synchronous commit; the acknowledged tick was admitted at that cut. No promise of wall-clock freshness at fsync completion is made. Driver cannot call a raw unguarded advancing commit or manufacture a certificate; only the guarded public MiniatureStore owner seam can obtain DurableAck.

## Atomic owner APIs

Proposed MiniatureStore APIs: create(path,genesis_spec,public_membership,BootstrapPolicy,&mut BootstrapSigner), open_existing(path,MiniatureKnownFrontiers), snapshot(), known_frontiers(), query_bound(request), issue_challenge(purpose,binding), accept_activity(ticket,proof), claim_authority(ticket,proof), prepare(intents,tickets,proofs), resume_pending(tickets,proofs), commit(&MiniatureBatch,owner_ticket,owner_proof), cancel_pending(owner_ticket,owner_proof), ack_outbox(operation). One transaction verifies current state/hash/frontiers, loads membership/authority, checks fresh proof or persisted-current admission, builds/validates typed transition and capacity/overflow, increments Store revision, writes full envelope/all exact mirrors, appends journal/snapshot, and for WorldCommit writes one events/batch row plus terminal request outcomes and bounded outbox. Component/schedules/holds/costs/outcomes/authority commit together. Then publish Accepted/DurableAck. Uncertain commit quarantines owner; reopen/query resolves status before retry. No tick/UI spendable amount/outbox delivery/ack escapes before commit.

Claim increments term and requires current role/device proof and fresh session. It leaves WorldTick/EventSeq/component/holds unchanged and clears leases. Pending is paused under old context until complete fresh resume or durable cancel; old context cannot commit. Resume preserves exact intent/input World, recomputes deterministic reservation/outcome plan there and atomically updates only authority/admission context. If any original actor cannot be freshly admitted, cancel whole Pending frontier, retaining every request binding and releasing its sole positive hold.

Commit rechecks current persisted term/session, source hash, actual next tick, event sequence and admission membership. Empty ticks require current authenticated activity and complete input. Cancellation additionally requires valid current authority proof/context; unauthenticated callers cannot cancel Pending. Policy-invalidated cancellation is AdmissionChanged, explicit authorized abandonment Cancelled. It uses current authority instead of old economic proofs and performs no debit/timer effect/tick advancement.
