# Cooperative capture/projection implementation and next native seam

Issue #11 depends on #10. This module separates campaign-thread capture/projection policy from IPC, canonical codecs and licensed APIs. Its only dependency is the public Java contract module. Workers receive bounded immutable values; they never receive `CaptureSource`, campaign ports, game objects or mutable maps. Actual native writer coverage, campaign-thread hooks and save/load integration are still unobserved, so every baseline certificate has **SHADOW_ONLY** eligibility.

The first subscribed input slice is faction weariness, relations and the configured minimum peace weariness. Float32 inputs preserve finite raw bits; no fixed-point conversion, strategic decision or Java numerical equivalence claim follows. The pinned [WarWearinessConcern source](https://github.com/Histidine91/Nexerelin/blob/a669f4d0740e95a4acbb6b894dde09ade67aa754/jars/sources/ExerelinCore/exerelin/campaign/ai/concern/WarWearinessConcern.java) reads manager/config state and inherited modifiers/lifecycle. This small input slice is insufficient to characterize the complete concern; #13 must inspect those additional dependencies before any replacement.

Implemented public seams:

- `CaptureSource.stamp() -> SourceStamp` and `read(Id aggregate) -> Input` are called only on the explicitly owned campaign thread. `SourceStamp` contains immutable context, observed mutation generation and the exact sorted subscribed revision read-set. Each input carries its aggregate and revision.
- `CampaignCapture(source, campaignThread, perFrame)` with `begin(frame)`, `advance(frame)`, `published()` and `invalidate()` captures at most eight aggregates per advance, with hard caps of 64 subscribed inputs and 8192 logical value bytes. Repeated calls in the same explicit frame share the same eight-item allowance, including after coalescing a capture. The native adapter must provide actual monotonically increasing campaign frame numbers. Logical byte/item bounds do not certify whole-process RSS or native frame-time cost. Its first and final stamps must agree; chunk drift discards the staged values. Repeated churn coalesces to the latest frontier; eight stale attempts impose a 32-frame backoff. Volatile-source failures discard staged data and return a static SOURCE error without leaking the source exception.
- `ObservedRevisions` is a bounded campaign-thread dirty index. Mutation hooks advance its generation and exact aggregate revision; context replacement invalidates queued work. It records only mutations delivered through that explicit port, so its certificate is cooperative observed evidence rather than proof that every native writer was intercepted.
- `ShadowProjection` stages a bounded immutable replacement in chunks, validates context/read-set/generation before each chunk and publication, then swaps one complete value view. The baseline exposes shadow publication only. Native offload proposals and canonical campaign mutations remain unavailable until a reviewed actual atomic apply seam and G1/G2 evidence exist.

Context binds universe, history, campaign, branch, runtime session, content hash, ruleset hash, provider and ownership generation. Lifecycle code must invalidate the capture and projection owners plus IPC `SessionFence` **before** load/restart/content replacement/exit and before polling a queued result. Current IPC `FrameBridge` is a separate single-producer/single-consumer prepared-byte queue; no capture schema is registered in the wire profile, and this module does not enqueue opaque bytes into the probe schema.

Saving while a shadow transition is staged reads the last complete immutable shadow checkpoint. No partly staged view becomes visible. `ShadowProjection.restore(View)` accepts only an exact current cooperative certificate and an empty local projection owner; unsigned sequence replay is idempotent and conflicting older/same-sequence results reject. That value-only rule does not certify a native Starsector save callback or an atomic multi-field mutation of live managers. Replaying an already published projection must be idempotent by sequence and exact payload, while same sequence/different payload fails closed. A revoked session or content/ownership/read-set drift abandons the stage.

Portable tests cover mutation between chunks, bounded count/bytes/work, context/session/ownership changes, wrong-thread access, finite churn/backoff, immutable handoff, staged save checkpoint, duplicate/conflicting apply and unavailable native mutation modes. Costs can be recorded for synthetic ports, but the p99 <=2 ms engineering target remains unmeasured in the actual game. Native G1 closure requires exact installed runtime identities, complete writer coverage, thread/lifecycle hooks and observed save/reload/repeated apply/frame-tail evidence.

# Required native adapter seam

The existing `NearFutureModPlugin` remains a compile-time API stub. A future owned disposable game experiment must bind `EveryFrameScript.advance(float)` to a verified campaign thread and monotonic frame counter, install/remove a transient script through inspected `SectorAPI` hooks, and keep source access inside that callback. `BaseModPlugin.onGameLoad`, `beforeGameSave`, `afterGameSave`, `onGameSaveFailed` and exit/restart handling require actual ordering/thread observations before wiring. Invalidation must precede queued apply. Cached artifact/content digests are prepared outside the campaign callback; no file hashing, socket waits, SQL, encoding bulk data or worker joins enter this module.

A persistent opaque mapping must translate native faction/config/relation identities into typed 16-byte aggregate identities for the bound campaign/branch, rather than object addresses, display names or save filenames. Every writer of subscribed facts must advance `ObservedRevisions`; direct DiplomacyManager mutations, configuration changes, inherited concern lifecycle and installed extension hooks need an exact writer inventory and coverage experiments. Unknown writers leave SHADOW_ONLY unchanged. Generation/revision exhaustion permanently poisons the observed index: LIMIT is followed by INACTIVE for every certificate/dirty/acknowledgement operation, including replace. Recovery is an explicit new lifecycle owner and fresh runtime session over re-read facts; the exhausted index cannot wrap, reset or issue another certificate.

There is currently no proved atomic native manager replacement, save-safe staged pointer swap, or verified interaction freeze for these live fields. `ShadowProjection` swaps only its own immutable value view. It returns NATIVE_UNAVAILABLE for OFFLOAD and CANONICAL modes. Offloaded decision support would require Java-authoritative read-set validation and acknowledgement/reconciliation; canonical projection would require a previously committed event and projection progress receipt. Those distinct paths have no native actuator in this portable module.

The input values are private in-process types, not a registered NF-CANON or Protobuf payload. Before crossing the reviewed IPC bridge, both Java and Rust must register an explicit required capability/schema with field/domain/type definitions and identical positive/malformed vectors. The existing probe schema cannot carry these opaque inputs. Transport workers may encode a received immutable snapshot after capture; they must never receive `CaptureSource` or game objects. The lifecycle composition root also invalidates IPC `SessionFence` before a transition.
