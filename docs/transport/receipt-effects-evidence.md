# Receipt effects and foreground lane

This is a moving author evidence record for the Phase A portable receipt slice. It does not certify whole issue #23, the future three-lane portal, native game responsiveness, semantic history/snapshot installation, or mutating network commands.

`ReceiptRepo` owns one existing profile-1 Store, one existing private vault, one loaded transport identity and one current membership lookup. Its configured ruleset must equal the actual Store world ruleset at opening and each current cut. Content remains an explicitly trusted configured/persisted context because the profile-1 Store has no content field. Original request/account/device/operation and the 133-byte RequestBinding digest remain immutable; that digest commits the full canonical intent digest.

The fixed book scans all 64 reserved names into at most eight summaries using the independently reviewed batch reader. Root, ACL, present corruption, gaps, unconfigured slots, anchor mismatches and tails fail closed. Recovery may adopt a later observational head only after checking the supplied external anchor and minima; a checksum chain does not establish rollback freshness. Returned heads require independently trusted retention. There is no automatic repair, name recycling, identity regeneration or saved grant. Public book append functions are observational metadata operations; only the opaque authenticated `VerifiedReceipt` path can produce a fresh accepted receipt after immutable persistence and the final current-policy/time cut.

`ReceiptLane` owns one actual TCP/Noise/Yamux Swarm. It exposes server/client construction from an opaque repository, one listen/dial, one anchored receipt query, one backend event per poll, encoded-custody metrics and shutdown. There is no supplied backend event, session installation, release ticket, mutable Swarm, Store or key getter. Exact request-response identifiers, actual Noise PeerId/ConnectionId, returned record digest, original operation deadline and current SQL epoch guard queued data. Finished ResponseSent gates server activation; verified Finished gates client activation. Only matched completion releases occupancy. The completion cut cannot unsend bytes: policy checks run before backend polling/queueing and again before activation/reporting, with no atomic remote-now revocation claim. Explicit shutdown drops the sole Swarm and pending upgrades/listeners. The selected parser/encoded queue limits and maintained Yamux transient parser allocation are separate from total heap/RSS.

Plain-record handshake/operation methods remain component transitions with no flush or backend-acceptance claim. Component retry tests now use fresh sessions, while the public paired-lane test covers repeated queries on the same actually completed session.
