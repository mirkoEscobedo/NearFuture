# Notification effects checkpoint

This scope implements the NF-NOTIFY-1 effects behind the opaque `NotifyLane` facade. It is a portable notification slice of issue #23. The three-lane Portal owner, its finite CLI, global resource accounting, notification flood fairness and the full issue acceptance remain pending.

One lane owns one maintained TCP/Noise/Yamux Swarm, one exact connection, private handshake/subscription state and exact request-response completion custody. It borrows the sole `ReceiptRepo` synchronously for fresh membership, current identity and retained request observations. No second Store, private-key getter, state-installation setter, supplied event completion or wire-triggered Store commit is exposed.

The public surface consists of `NotifyLane`, `NotifyLaneEvent`, static `NotifyPolicy`, data-only statistics and structural codecs/behaviour types. Authenticated session, handshake, broker, subscriber, permit, flow and emission types are crate-private. Direct component regressions live under `cfg(test)`; external paired-lane tests use the public facade.

A subscription selects the authenticated principal's exact retained request, operation and immutable binding. Challenges are consumed on the first attempt. Every protected lookup, sign, queue and completion checks the current repository policy and actual peer/connection. Membership changes refuse the prior session. Client lifetime starts immediately before its own Begin; server lifetime starts at final Prove admission before signing Subscribed. Neither response nor Notice/Ack renews it.

A Notice is a dirty hint with an ordered subscription sequence. It carries no remote Store or event frontier and cannot establish a durable outcome. The client preserves its original request and dirty state on failure. Only an opaque completion minted by the actual receipt lane after verified Status persistence can cover a privately issued query nonce and generation. A correlated query also carries the subscriber's private absolute OwnBegin lifetime end into the receipt owner as an additional rejection-only deadline; the receipt operation's own five-second window cannot renew it. Uncorrelated receipts cannot clear dirty state; a newer Notice while a query is in flight remains dirty after that older completion.

All protocol bodies plus four-byte framing, not only Notices, reserve fixed queue and rate capacity before signing/enqueue. The initial handshake's budget is inherited by the subscription. Matching maintained backend IDs and actual endpoint release custody; Subscribed must be flushed before Notice. A dirty marker coalesces retained transitions without an unbounded notice queue. Low selected burst/rate values may refuse a rapid startup; they are never silently widened. The observed paired tests cover default limits and queue-items one.

The private monotonic deadlines have wakeable timers and cooperative elapsed checks before and after resumed repository effects, inside protected callbacks before signing/verification, before state/custody admission, immediately before owner enqueue and before another backend poll. Final completion also retains the original setup or awaited five-second end through protected SQL, before reporting, clearing pending state or releasing encoded custody; later owner timers and active lifetime cannot renew that origin. These are refusal cuts, not authority or a hard real-time scheduling guarantee. The owner codec's fixed four-second whole-request read precedes the maintained five-second operation deadline; completed input past four seconds is refused even if the timer driver lagged. Bounded read/decode refusal becomes local `Rejected` data so the real owner sees the peer/connection/ID. Rejected has no wire encoding, signature or Store mutation. Dropping a lane drops its owned Swarm; cancellation accounting and process RSS are separate unmeasured properties.

Verification records are in `notification-effects-verification.md`. Production and tests are author-frozen at notification-effects-checkpoint.json for independent R2 after one semantic repair round; owner integration awaits that review. Game integration and native operational authority are outside this checkpoint.
