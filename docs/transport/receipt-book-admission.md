# Receipt book absence and inventory admission supplement

Documentation-only dependency/API supplement to the frozen [receipt-contract.md](receipt-contract.md), SHA256 `763fbd65d5d6df42268c6b30d3ddaf3bea23972303fa7b0ab5f618ab58f31efd`. Its fixed control2/transcript/book records and independent receipt vectors are unchanged. This supplement resolves a concrete absence/corruption ambiguity before source implementation; it does not claim the new identity seam or book owner has been implemented or tested.

## Required additive vault seam

Accepted `PrivateVault::read_private_blob` reports `IdentityError::MissingLocalState` for both absent files and present malformed size/prefix/checksum. The book must never interpret that error as an empty slot or end of a journal. A private root/path exists inside identity, and receipt code cannot correctly distinguish absence by probing that path itself.

Root owns a minimal additive identity effect API and its independent review:

```rust
impl PrivateVault {
    pub fn read_optional_private_blob(&self, name: &str)
        -> Result<Option<Vec<u8>>, IdentityError>;
}
```

Keep accepted `read_private_blob`, create/remove behavior, key formats, 46-byte NF-BLOB-1 wrapper, names, ACL policy and all existing callers unchanged. There is no new optional key/identity read, existence boolean, path/root getter, write/grant setter or Store schema change. Returned bytes retain the existing private-data handling obligation: bounded ownership, no diagnostics, and wiping when secret-bearing.

Normative optional-read outcome is `Ok(None)` only when the exact validated blob name has no directory entry and the actual OS no-follow entry lookup returns NotFound, after the configured vault root has passed its existing owner/access checks. This is explicit absence of that named record, not an error translation from the old reader. Revalidate root access on the NotFound return branch so an already missing/inaccessible configured root is never treated as an empty book. Do not use `Path::exists()` to decide absence (which conflates failure), and do not call the old reader then translate MissingLocalState to None.

Use the existing validated ASCII1..64 blob-name resolver/prefix and validate the configured private root first. Perform a no-follow entry admission with maintained standard filesystem APIs. Any present symlink/reparse point, directory/nonregular object or rejected private access is an error; a dangling link is present, never None. Every non-NotFound entry lookup failure is an error. On Windows, inspect the maintained MetadataExt file attributes for FILE_ATTRIBUTE_REPARSE_POINT as well as the ordinary file type; no root or caller-visible arbitrary path is exposed.

After present-entry/type admission the additive method may delegate to the accepted existing read method and propagate every error unchanged; no delegated error becomes None. For an admitted present regular entry, check owner ACL/mode and open that exact file once for bounded reading. If it disappears before open, opening NotFound is an error in this present-entry branch, not absence. Use metadata from the opened handle, enforce46..4142 wrapper bytes, and read at most4143 bytes through that handle. Growth/overlength, read/metadata failure, wrong prefix/count/checksum or changed exact length returns an error. Require exact length/count<=4096 plus the accepted SHA256 wrapper check; only a valid present wrapper returns Some(payload). Present corruption may retain the existing static MissingLocalState classification, because the optional outcome clearly distinguishes it from None. Inaccessible data remains an error, with no diagnostic path/data disclosure.

ACL/entry checks and opening are separate safe API steps. This does not claim an atomic filesystem snapshot, handle-relative cross-platform ACL validation or safety against concurrent same-owner replacement. The owner-local cooperative lifecycle contract remains mandatory: no caller removes/replaces/reuses reserved book names during the repository lifecycle. A racing removal after entry admission fails closed; this proposal does not create a concurrent lifecycle lock. Root/identity reviewer must inspect actual Windows regular/reparse and Linux owner-mode behavior before accepting the implementation.

## Closed bounded book inventory

The receipt repository owns exactly the64 reserved names `receipt-r0-g0` through `receipt-r7-g7`. It obtains no directory iterator/path/root and accepts no peer-supplied name. For each recovery pass, call the strict optional API for all64 exact names, including unconfigured request slots and every generation beyond an apparently absent next entry. This is a finite admission pass, never an unbounded directory scan. Unrelated accepted identity/IPC/transport vault blobs remain allowed. Out-of-range receipt-like filenames are outside this reserved inventory, are not enumerated, and can never be admitted as a generation; no arbitrary glob/unknown-file detection is promised. The contract's unknown-root/gap/tail refusal means present data inside these64 reserved names or a mismatch with externally configured anchors. It cannot claim detection of arbitrary files outside that set.

A trusted external inventory supplies the configured slot set, immutable original descriptor and exact `(slot, generation, SHA256(record))` anchor plus protected remote event/store/member minima. Reject duplicate slot anchors or out-of-range slot/generation before any book allocation. For an unconfigured slot, every reserved generation must be None; any valid or invalid present root/tail rejects rather than adopting another principal/request. A configured slot must have a valid present generation0 and a consecutive valid chain through its highest present generation, and must contain its exact anchored generation/hash. If a lower generation is absent while a later one is present, reject the gap. A configured root missing entirely rejects; None does not authorize creating/relabeling it. Present corrupt/inaccessible records always propagate refusal, including a tail after the highest valid generation.

For every Some payload, require exact479 bytes and the frozen closed book version/profile/field widths. Validate generation against its reserved name, original RequestId/op/account/device/scope/server pin/kind/payload_digest/derived133-byte binding, zero previous digest at generation0, exact previous-record SHA thereafter, monotone remote minima and admitted phase/sequence progression. Generation/head anchors protect the exact chain prefix, not a session permission. Do not normalize another descriptor, skip malformed suffixes, choose a competing root or import saved terminal metadata as an active grant.

Probe/read and decode one record at a time into fixed per-slot summaries, retaining bounded previous digest/descriptor and anchor state. Admission covers at most64 NF-BLOB wrappers (each ceiling4142) and64 fixed479-byte book records; do not retain64 maximal private payload buffers merely to enumerate them. Return no usable partial inventory if any name fails admission. A later re-read before append detects sequential replacement through the full validated expected prefix; concurrent same-owner replacement remains unsupported.

Explicit first-time initialization is a separate trusted owner action with an independently retained original typed RequestBinding and selected unconfigured slot. It performs a full closed inventory admission, confirms all8 names of the chosen slot are strictly absent, then create_new/write/sync generation0 with the exact original descriptor. It returns the resulting head anchor for independent trusted retention; absence alone never creates a request ID. A create collision or failed write/sync refuses readiness without rewriting/removing existing bytes. Recovery never performs initialization automatically. Capacity is finite and a request/slot is never silently recycled.

## Append, anchors and failures

Append admits the entire currently configured inventory first, requires the expected existing highest generation/head, and uses create_new for the exact next fixed name. The next record repeats the immutable original descriptor and links the old exact SHA, with monotone minima/phase. Existing generation bytes remain immutable. At generation7 or exhausted slots, return local Busy before reporting any fresh receipt whose increased minima/phase require persistence. Equal admitted metadata may remain read-only without consuming another generation.

A failed append preserves the old valid prefix and returns no fresh public receipt or raised protected minima. A partial/new corrupt tail remains visible to strict optional admission and blocks later recovery/append; never silently skip it or fall back to the older prefix. There is no automatic retry overwrite or deletion. Explicit trusted repair can remove only the exact owned failed name after comparing its expected prefix/context under the exclusive lifecycle contract, preserving old valid records. That repair does not waive external anchors or invent a transaction acknowledgement.

Private wrapper checksums and book SHA links cannot detect deletion to an older valid prefix. Independently retained inventory/generation/head anchors and remote minima remain required for any backup rollback-protection claim. The implementation must state which actual trusted owner component supplies and retains those anchors; storing another unauthenticated anchor beside the same rollbackable book does not establish independent freshness. No optional read advances an anchor, authority, membership or canonical World. Saved terminal metadata is a last-known observational view; every reconnect still uses fresh peer/session/current-membership proof and exact original query.

## Shared repository ports and implementation ownership

Receipt owns new `receipt/**` and the single `ReceiptRepository`; notification/portal owner consumes narrow crate-private ports described in [notification-api-proposal.md](notification-api-proposal.md). Agree to `local_public`, typed original-derived `ReceiptSelector`, exact `observe_selector` with fresh active membership epoch, and synchronous higher-ranked `with_current_read`. None exposes a Store handle or arbitrary mutation callback. Root owns shared exports/builders/wiring and the identity optional read. This supplement does not change those owners' files.

`CurrentRead<'a>` borrows freshly loaded/validated MembershipState, exact local PublicIdentity and its non-Clone SecretSeed only during a synchronous HRTB closure returning lifetime-independent R. The closure can use accepted bulk/auth methods unchanged; it cannot await or retain borrowed policy/signer references. Owned observations can be returned but never treated as later grants. Current lookup validates scope/ruleset, owner role where configured, local key/actual peer and known frontier consistency; the protocol state then verifies both endpoints/current epoch/actual ConnectionId/session and its exact purpose transcript. Every protected stage and flush obtains a new cut. This is trusted crate-internal signing, not a public unchecked sign-anything authorization API.

`ReceiptSelector` fields remain private. Client selectors derive from its immutable OriginalReceipt and actual local principal/scope. Server subscription selector admission has a separate typed constructor using its active authenticated peer/principal/device/session context and decoded RequestId/op/binding, then exact retained lookup; a server must not call the client-local selector constructor to relabel a remote principal. `observe_selector` rechecks that current policy and retained account/device/op/binding match, rejects Unknown for subscription baseline, and returns metadata only. No receipt or hint is installed from a caller-created projection.

Agree to a named typed `TrustedPreparedCommit`/`commit_trusted_prepared` owner seam for the actual server-owned transition oracle, rather than `owner_store_mut` or FnMut(&mut Store). Trusted local setup prepares through accepted Store APIs before transfer of ownership and seals its real CommittedBatch plus expected before-state digest/source revision/selector. The owner checks the exact pending operation and before context, consumes the command once and invokes the accepted Store commit. Wrong/stale batches refuse; accepted Store itself validates admitted intents/authority/frontier before durable Ack. This command has no record decoder, peer JSON conversion, public wire operation or production serve/watch mutation command. Its real commit is used only by explicit trusted fixture orchestration in this first slice. Notification dirtiness follows an actual retained projection change, never a fake phase/Ack or Store outbox acknowledgement.

No dependency additions or accepted control1/bulk1/Store byte changes are proposed. Existing Noise transport identity loads rather than regenerates; root's additive private-key lane builders delegate to independently owned codecs with no raw key export. Notification's separate namespace/session/proof cannot admit a receipt, and receipt's stored book cannot authorize a notification acknowledgement.

## Required RED/GREEN and review evidence

Identity seam behavior tests must compile first and cover strict None for genuine absence, valid Some, malformed size/prefix/count/checksum, truncated/overgrown wrapper, inaccessible/reparse/nonregular present entry and missing configured root. No old-reader regression changes are accepted. Cross-platform effects require actual Windows owner ACL/reparse and hosted Linux owner-mode evidence; pure byte tests alone do not prove filesystem admission.

Book owner public behavior then covers unconfigured present root, corrupt tail after apparent end, generation gaps, exact anchored prefix deletion/rollback, another principal/pin, maximum64 inventory, failed new-generation write preserving old bytes/no fresh result and finite Busy. Use independently generated frozen479-byte fixtures through the actual owner/vault path with real disposable private vaults; no MissingLocalState-to-absence stub. A compiled valid book fixture must fail the intended corruption/gap assertion for meaningful RED, rather than a missing-symbol/setup failure. Native owned-child Job Object/process deadlines/readiness and Linux equivalents apply to actual peer fixtures.
