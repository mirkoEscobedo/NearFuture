# Local Chat outgoing status over authenticated IPC

This profile adds only a read-only outgoing-status query to the existing foreground NodeServer. The trusted supervisor supplies the private vault, full local peer pin, ChatStore and ClientOutbox. Each query checks current durable PLAYER membership, account/device keys, revocation, peer and scope. It has no financial store, economic operation, remote key enrollment, post, receipt issuance or acknowledgment endpoint.

ControlEnvelope fields19 and20 carry QueryChatOutgoing and ChatOutgoingStatus. These two bodies require exactly capability3/schema3; all existing bodies still use the unchanged schema1 registry. Local token authentication keeps its existing capability2/schema2 transcript and limits. A query binds its own request ID separately from the immutable original request, message ID, local principal and universe/history. A status retains those fields plus per-sender source sequence, outbox revision, canonical signed original and Pending or Delivered. Pending has no receipt; Delivered carries the exact323-byte retained receiver receipt already verified by ClientOutbox. Missing history remains a refusal, never Expired. There is no global-order or permanent-availability claim.

The signed original is174..2221bytes and the receipt0or323bytes. The largest status body is2698bytes; its minimal envelope is2723bytes, below the existing4096-byte per-connection turn. Protobuf preflight enforces those field bounds before allocating byte vectors. Client response admission validates runtime, query/original/principal/scope/message correlation and canonical original/receipt binding. This is a trusted local status report; shape decoding alone grants no remote signature authority or game effects. Unknown fields and capabilities remain closed. Profile3 is not accepted for existing operation or handshake bodies; legacy financial canonical records are unchanged.
