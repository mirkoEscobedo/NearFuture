# Permitted remote Chat history: qualified first path

The bounded history protocol runs on the existing production Chat Noise Swarm and sole foreground ChatStore owner. One unchanged independent physical case first reached authentic Unsupported instead of its expected Page, then passed after the owner called the real ChatStore.history with the same query, ticket, proof and observed peer. The existing delivery protocol, canonical bytes, sender receipt issuer, outbox schema, original tests, private identities and user saves remain unchanged.

The new /nearfuture/chat/history/1 profile uses domain NF-CHAT-HISTORY-WIRE-1 followed by a zero byte. Every body contains domain23, tag1, policy digest32, request16, reader account16, reader device16, General channel1, after-cursor8 and limit2: a115-byte common header. Five closed tags carry Challenge(no suffix), Proof(ticket16 plus DeviceProof170+peer<=128), Issued(ticket16/challenge32/membership8), Page(next8/count1 plus at most one entry cursor8/length2/canonical SignedMessage<=2221), or Refused(one closed existing refusal code). Maximums are115/429/171/2355/116 bytes respectively. All integers are big-endian; the four-byte external length is excluded. Framing checks115..4096 before allocation, exact EOF and canonical re-encoding; signature authority is checked later.

Wire callers explicitly choose limit1. The value encoder/decoder and fetch_history API validate limits0 and2..64 as PeerError::Limit instead of silently truncating; an invalid limit in a raw wire frame fails framing with InvalidData and closes the connection before ticket issuance, rather than receiving an authenticated Refused response. Local ChatStore history retains its existing1..64 profile. A Page contains zero or one full signed original, advances next_cursor to exactly the returned receiver_cursor, and leaves next_cursor equal to after_cursor when empty. The cursor is only this receiver's pagination position. Sender sequence remains per-account/device. Neither is a federated or global total order; pages do not promise permanent or complete availability.

The physical builder supports the separate profile without changing /nearfuture/chat/1. To retain the aggregate two-stream ceiling, each request_response behaviour gets one concurrent stream, rather than two streams each. The existing owner reserves the same two worst-case4096-byte response slots across both protocols, and shares the existing64-exchange/five-second proof budget and one admitted physical connection. Membership changes and disconnects invalidate both exchange classes. Any cross-kind presented ticket also consumes the other adapter admission; response request IDs are keyed with the protocol kind to prevent namespace collision. This is an explicit narrower post-stream configuration. The qualified history case includes one successful sequential production post/receipt/ack under this configuration; it does not establish simultaneous pressure or a rerun of the older nine controls.

HistoryChallenge calls the real store challenge API with the exact query and observed Noise peer. HistoryProof removes its physical adapter admission once and verifies the current reader proof, policy digest, request, reader, channel, after_cursor, limit, query binding, current membership revision, ticket age and exact physical ConnectionId. The qualified minimum GREEN calls ChatStore.history using that same query, ticket, proof and observed peer. The real transaction consumes the store ticket and reads permitted originals without history/frontier writes. The earlier Unsupported scaffold and its authentic failure evidence remain preserved.

The client begins one absolute five-second deadline before current private identity loading, checks after synchronous helpers and while polling, and never resets the deadline on responses. Blocking vault helpers are not preempted by Tokio. Address length stays128 with explicit trusted loopback IPv4/TCP/final P2p. Current LOCAL membership and the retained receiver pin authorize the receiver and reader; wire fields cannot enroll keys. A returned page must match the actual Noise peer, connection, outbound request ID and entire query/context. Each source message must match scope/channel and a known account/device key with a valid author signature. A historically revoked author's valid retained signature may remain readable; it grants no new posting authority. Unknown keys are refused.
