# Protocol v1 wire contract

The schema source is `protocol/near_future/v1/near_future.proto`. Generate Rust with maintained `prost`/`prost-build` and Java with maintained Protocol Buffers; do not hand-write wire parsers as a replacement for those libraries. Rust generation and the boundary validator now live in `crates/nf-wire`, using exact prost/prost-types/prost-build 0.13.5 and protoc-bin-vendored 3.2.0 (libprotoc 31.1). They are separate from the NF-002 bootstrap. Java generation and parity are recorded by the integrated NF-003 evidence. The accompanying [canonical profile](nf-canon-1.md) defines bytes/hash identity independently of protobuf serialization.

Semantic IDs use distinct protobuf messages, each exactly 16 raw bytes, even though their binary widths match. Digest values are exactly 32 bytes. A PeerId is a validated libp2p multihash up to 128 bytes, never an AccountId or DeviceId. No generation algorithm or UUID normalization is implied. Account/device authorization is external authenticated policy. Zero-valued byte arrays do not bypass authorization.

AuthorityTerm, RuntimeSession, RulesetRevision, WorldTick, EventSequence, AggregateRevision and MembershipRevision are separate fixed64 wrappers. No term/session replacement silently advances the world tick or creates a new lineage. Required message presence is validated explicitly. Wire uint32 schema IDs/type selectors must fit their registered domain; only canonical header values use u16.

## Boundary sequence

1. Read a u32 **big-endian** control-frame length, reject zero or more than 1 MiB before allocating a frame. The frame itself is one ControlEnvelope protobuf message. Bulk framing/transport is a later adapter; SnapshotChunk is a bounded data contract, not a socket implementation.
2. Preflight bounded protobuf structure before generated decode: message depth <=32, collection/field counts and cumulative bytes within the canonical profile's hard caps, valid shortest varints within declared scalar widths, known wire types, no group tags. Reject invalid field zero, overlong varints, truncation and duplicate occurrences of any singular/message/optional/oneof member. A oneof must occur exactly once when required. Packed repeated primitives may be one length-delimited occurrence; unpacked repeated entries may occur repeatedly within count bounds. Never accept both packed and unpacked encoding for the same field in one message. Preflight is a boundary guard; maintained generated code handles the subsequent actual wire decoding.
3. Decode with configured size/recursion limits where supported; also enforce the frame-wide cap. A decode returning success is not validation. Rust preflight charges 256 logical allocation-budget bytes per known nested message, 8 per scalar and the byte length of strings/byte fields, with cumulative cap 1 MiB; unknown observation fields are charged too. This conservative preflight budget and fixed document/count caps bound work and generated allocations; they are not a measured total process-memory or allocator guarantee. Canonical conversion may hold bounded copies transiently. Reject invalid UTF-8, zero enum selectors, unrecognized operation kind, wrong ID/digest widths, missing required messages, contradictory phase/outcome, duplicate IDs/map keys or unsupported semantics.
4. Build validated typed domain records, check all required schema/capability sets, canonicalize according to the closed registry, verify provided digests/signature and authenticated identity/history/session. Verify declared envelope Required equals body Required when present. Unknown optional capability IDs may be ignored only if neither declared required nor used by the body. Optional transport metadata cannot affect domain decisions.
5. Authorize and check expiry/revisions/request binding before handing the value to a mutation/commit boundary. No partially decoded object can escape as state or a proposal. Failed parsing/validation does not create dedup outcomes or modify persisted state.

Singular duplicate rejection deliberately tightens protobuf's standard last-value/merge behavior. Generated libraries alone do not establish this property. Protobuf maps are avoided: repeated AggregateVersion records are treated as sorted maps, and duplicate semantic keys reject even if their protobuf encodings differ.

Unknown fields in semantic messages or ControlEnvelope reject in v1: they might encode unrecognized meaning. Unknown fields inside TransportMetadata may be skipped/discarded within the frame/depth/count limits because this submessage is restricted to observation-only data. No canonical profile reads that submessage. A future implementation cannot use an ignored field to alter permissions, expiry, prices, retry identity or proposed state. Unknown Required capability/schema IDs reject with UNKNOWN_REQUIRED_SEMANTIC rather than silently dropping them.

## Negotiation, status and bulk state

Handshake is the only permitted pre-authentication semantic body. It has protocol minimum/maximum (nonzero and min <= max), required sets, optional capability set, typed universe/history/session, ruleset/content policy digests and limits. Local IPC session_token is exactly 32 unpredictable bytes supplied through the owner-private rendezvous mechanism; it never enters canonical state, signatures, errors or logs. Network identity has its own later transport policy and must not reuse this token as an account key.

Negotiate the greatest common supported version and component-wise minimum limits, bounded by implementation caps. Required semantics must be supported by both sides. Protocol/history/session/ruleset/content mismatch produces a bounded useful explanation and no session activation. Client-supplied limits never increase server allocation or queue ceilings. An absent, zero or internally inconsistent limit rejects. No fallback to a less strict semantic schema occurs silently.

The schema defines data shapes for later handlers; v1 currently registers only the non-mutating contract-probe operation/payload. CancelOperation has no registered cancellation payload yet and must return unsupported rather than mutate a target. Query authorization/status and cancellation execution belong to later operation lifecycle implementations. An accepted request can yield ACCEPTED/PENDING/final OperationStatus; accepted is not committed success. QueryOperation uses the same RequestId, principal, universe and history. Cancellation uses its own RequestId and names the target; CANCELLED is a durable terminal outcome only when effect prevention was established. Cancellation races can return an already committed success. Status request_binding_digest identifies the durable original binding, and querying requires authorization. Reuse conflicts never return an unrelated earlier success.

WorldSnapshot and EventBatch carry the distinct histories/counters described by NF-CANON-1. Canonical state_hash excludes its own field; event batches bind previous batch hash and resulting state hash. Proposal is a data-only candidate with ruleset/input/session/read/write-set provenance; a successful decode grants no authority to commit it.

SnapshotChunk data is <=256 KiB, chunk_count 1..256, chunk_index < chunk_count, and total_bytes 1..64 MiB. Chunks for a transfer must agree on digest/count/total; duplicate indices reject unless byte-identical and explicitly treated as a retry. Checked aggregate byte accounting never exceeds the declared total or quota. Assemble only after all chunks arrive, validate exact total/digest and canonical document limit before installation. In this baseline, a document still has a 1 MiB canonical cap, so a larger completed transfer cannot be interpreted as a single WorldSnapshot; segmentation requires a registered future schema. Compression is disabled. Backpressure bounds bytes and items; transactions are never silently coalesced/dropped.

Errors contain a recognized enum, an NFC reason <=512 UTF-8 bytes, bounded sorted unsupported-ID lists, and retryable boolean. Reasons disclose only public compatibility context; no stack traces, usernames, paths, tokens or private state. A decoder failure incapable of producing a safe bounded error closes the session.

## Test obligations and current evidence

The JSON canonical vectors are independent golden inputs for both languages, including malformed bytes and request-binding mutations. They do not test protobuf decoding. Wire tests must separately send singular duplicates/oneof conflicts, width violations, recursively excessive messages, huge lengths/counts, unknown semantic fields, ignored optional transport fields and unsupported Required sets. Fuzz both preflight/generated decode and canonical decoding with explicit allocation/work counters. Observe no mutation even when generated decode succeeds for an input the stricter boundary rejects.

This schema/specification does not establish transport, persistence, cryptographic verification or licensed-game integration. NF-003 acceptance requires generated Java/Rust contracts, cross-language byte/hash equality, bounded input rejection/fuzz evidence and request-conflict tests. No GitHub issue should close on these documents alone.


Current Rust public seams are `nf_wire::decode_control`, `decode_control_with_limits`, `decode_frame`, `decode_snapshot` and `decode_chunk`. They return generated data values only after strict preflight and applicable canonical record checks. `WireError::bounded_error` returns a safe static explanation. `generated` types remain wire adapters, not authenticated domain authority. The baseline signature field must be absent/empty or exactly 64 bytes for Ed25519; the generic 128-byte hard cap permits no additional algorithm. Shape admission is not signature verification. Runtime/identity callers must verify signatures, bound principals, expected universe/history/session/ruleset and operation policy before mutation. QueryOperation has only shape admission here; cancellation fails closed. Chunk admission checks one chunk's quotas/shape and performs no transfer assembly, reservation or installation.
