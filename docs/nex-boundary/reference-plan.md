# Isolated reference checkpoint and remaining limits

The isolated Java17 `nex-reference` module was delivered for a bounded adapted-source slice in [PR #54](https://github.com/mirkoEscobedo/NearFuture/pull/54), merged as `39a113c2389c90f585aaecbed163a9231d55622d`. It uses ordinary copied inputs and JDK collections, with no original Nex JAR, proprietary API JAR, Global, live manager, resource spend, relationship change or duplicate manager registration. Adapted sources retain the pinned MIT notice and identify original commit/blob/method and deliberate effect-boundary substitutions. [Current verification](../nex-reference/verification.md) and [source adaptation](../nex-reference/source-adaptation.md) record the delivered scope and remaining gaps.

The first oracle adapts `WarWearinessConcern.generate/update/isValid` and the required `BaseStrategicConcern` lifecycle plus `SAIUtils` priority expressions. Outputs retain ended/generated/valid/action-abort facts and an ordered priority mutation trace. Trace values compare exact raw f32 bits. Proprietary MutableStat aggregation and its iteration/storage behavior are not guessed: total priority equivalence needs captured API reference evidence. Config changes must exercise stale existing modifiers, ended objects and newly created restart objects separately.

The second oracle selects one explicitly supplied non-player enemy. It adapts `checkPeace` eligibility guards and `tryMakePeace` weariness/event/player-level arithmetic, consuming explicitly supplied ordered `Math.random` double values. It returns an immutable ceasefire/treaty proposal and expected weariness-reduction trace, replacing live event creation and weariness writes with result data. The source first calculates a float chance and compares a Java double random draw; retaining only f32 RNG would lose information. The proposed RNG extension therefore stores finite double bits as u64 with exact purpose and ordinal. No random source, hidden seed or broad epsilon is used.

The selected-target input needs explicit enemy membership, pirate/config gate, elapsed days since last war, recent-war marker, pair ceasefire eligibility, commission/player flags, offensive-blocking facts, both adjusted weariness values, both event dispositions, level/divisor settings, hostile-versus-vengeful classification, treaty chance, reduction settings and relevant cooldown. Missing or uncontrolled facts make the oracle unavailable. Multi-enemy sort/three-try traversal, player prompt/delegate state and live application remain separately uncharacterized.

The delivered synthetic corpus contains 10 concern and 16 selected-peace cases, including immediate f32 threshold neighbors, missing/active/ended concerns, modifier combinations, termination/new-instance restart, config changes, selected eligibility failures, adjacent double draws and conditional second-draw consumption. Tests exercise only the adapted reference on copied inputs. Real captured ordering, installed behavior and whole-slice equivalence remain unobserved; a Rust port must compare independent recorded outputs rather than manufacture expected results from shared implementation.

Certificate scope remains adapted-source reference evaluation. It does not establish source-to-installed-JAR equivalence, proprietary priority aggregation, real captured coherence, shadow equivalence, writer suppression or authority eligibility. Those gates remain #11/#13/#14 observations, and no game integration acceptance is inferred from a synthetic Java run.
