# Integration feasibility and experiments

API inspection ran against the locally supplied game/mod JARs. Only public signatures were inspected (`javap`, no `-c`/implementation decompilation). Artifact hashes are recorded in [observed-installation.json](observed-installation.json). Source links use immutable pins. **Every game experiment below is untested/blocked**: no installed Near Future adapter or disposable campaign test harness exists yet. A blocked game test is not replaced by a mock pass.

Reproduce signature checks locally without shipping game binaries:

```powershell
javap -constants -classpath "$env:STARSECTOR_HOME/starsector-core/starfarer_obf.jar" com.fs.starfarer.Version
javap -classpath "$env:STARSECTOR_HOME/starsector-core/starfarer.api.jar" com.fs.starfarer.api.BaseModPlugin com.fs.starfarer.api.EveryFrameScript com.fs.starfarer.api.campaign.SectorAPI
# Set CONSOLE_JAR to your owner-supplied Console Commands JAR.
javap -classpath $env:CONSOLE_JAR org.lazywizard.console.CommandListener org.lazywizard.console.Console
```

The actual public version constant was `0.98a-RC8`; JVM `jre/release` identifies Azul Java `17.0.10+7-LTS`, Windows x86_64. Console metadata requires 0.98a-RC5 and Nex requires 0.98a-RC8; those strings are requirements. Presence of a method, library or `--add-opens` flag does not prove Starsector's script classloader permits a call. See the [debugging guide](../starsector-debugging.md) for the pinned AutoColonyManager investigation, save-safe tests, reflection restrictions and UI/log pitfalls.

Supported means all required gates for a named capability passed on exact hashes. Experimentally supported means named experiments passed with explicit restrictions. Unknown means evidence stops at inventory/signatures/source. G6 performance remains untested independently of G1–G5: compilation, Rust usage and shadow duplication do not establish acceleration.
