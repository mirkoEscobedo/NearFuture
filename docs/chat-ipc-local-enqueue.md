# Owner-local Chat enqueue over authenticated IPC

The dedicated EnqueueChat command uses capability4/schema4, separate from financial1, token-authentication2 and readonly outgoing-status3. The trusted owner checks current PLAYER membership, scope, account/device key and full local peer against the private vault and retained outbox policy. Callers supply bounded canonical text and an original request ID, never message ID, sender sequence, signing seed or lifetime pins. No remote history write, receipt issuance or delivery claim follows from local enqueue.

A new original is signed by the retained local sender and committed atomically as Pending with the next per-sender sequence and outbox revision. Exact original retries return the retained original, including a genuine Delivered receipt, before capacity or sequence allocation. A divergent same original is refused without replacing its first message or changing SQL bytes, frontiers or revision. Conflict is reported as the existing Malformed code only through this dedicated command; generic operation errors and canonical schema records are unchanged.

The original whole physical IPC case reached Unsupported versus Pending after actual mutual token authentication and current membership checks. Its unchanged same-case GREEN passed5.64s and reached the canonical device signature, original/source/revision, closed SQL-byte comparisons, fresh-session reopen and exact retry assertions. Seven independent controls then qualified across six initial passes and one divergence RED followed by the unchanged divergence case passing5.93s. They cover next sequence, exact Delivered retry, current account-signed revocation, wrong seed and sender lifetime pins, exhausted sequence, and divergent request zero effects. The divergence failure exposed a server/client error-code translation gap, repaired without changing its Malformed literal or storage policy. These were separate selected runs, not a single seven-case GREEN replay.

Dedicated serve-chat-command now mounts this CommandPort under the existing foreground owner and trusted private-vault lifetime checks. The unchanged CLI/headless-Java first case naturally failed at the absent CLI command, then at Java Unsupported after actual mutual authentication. The real CLI mount and receive-only profile4 reply admission produced one whole PASS in 31.32 seconds, reaching independent sender-signature verification, unchanged receiver SQL bytes/frontiers, durable outbox reopen and a fresh-runtime exact retry with the same signed original. Ordinary :wire:check also passed six new reply-admission groups with 23 negative variants, alongside the existing auth/corpus/boundary/policy controls; these pure decoder checks do not authenticate placeholder signatures.

This qualification covers standalone owner-local enqueue and a scoped headless Java consumer. It does not supply a public Java enqueue client, remote delivery composition, presence, moderation, retention or game/UI lifecycle integration. Existing deadlines, financial/auth/readonly profiles, original source and failure captures, and published draft PR79 remain preserved. Issue #25 is incomplete.
