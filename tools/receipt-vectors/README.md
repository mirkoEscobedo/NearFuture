# Independent Control2 receipt fixtures

Test-only Node Buffer/standard crypto writer for the accepted receipt design. No production codec, Rust-generated byte output, operational identity, authorization decision or native payload is imported. The producer is independently owned; production authors must not edit it. Corpus expectations are proposed data classifications until separately observed through frozen public production seams.

The contract identity is SHA256 of UTF-8 LF-normalized `docs/transport/receipt-contract.md`: `763fbd65d5d6df42268c6b30d3ddaf3bea23972303fa7b0ab5f618ab58f31efd`. LF normalization admits ordinary Git CRLF checkout differences only. It does not admit semantic contract drift. Generation fails if this pinned identity changes. JSON contains scenario metadata; the six-column TSV carries category/name/layer/expectation/hex/SHA256 for bounded consumers. Every byte output uses LF. No shared scripts, manifests, locks or production APIs are changed by this producer.

`node tools/receipt-vectors/generate.cjs` writes both artifacts. `node tools/receipt-vectors/generate.cjs --check` requires exact existing bytes. Other arguments reject. The only dependencies are Node's built-in Buffer, crypto, fs, path, test and assert modules. The SHA and Ed25519 primitives are maintained Node implementations; the writer performs no custom cryptographic arithmetic.

The two seed constants are explicitly public RFC8032 test seeds, paired with their known public keys. Their presence is public synthetic test data, not operational credentials or a configured account. Fixture PeerIds use the canonical inline Ed25519 public-key prefix `002408011220` plus those32 public bytes. Real runtime grant tests must use fresh generated private identities and admitted membership instead of these seeds. No seed appears in a book record or DeviceProof wire body.
