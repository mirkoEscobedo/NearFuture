## Independent review repair round1

Root's independent Review R1 identified that the initial fixture reused operation nonces for Sync and Document, allowing the Install test to miss control-nonce substitution. A new test used the existing transfer and install APIs with distinct document values. It failed on the actual transcript client-nonce bytes: control0x11 appeared instead of document0x1e. This is an executable behavioral RED, not a missing-field/API/import failure. The result is `.tmp/sync-reference-nonce-red.json`, SHA256 `b58900e7004cd3769c1b0aa558b673682344704f73f677640d511e265a37e9f7`; one failure, status1, no timeout, Windows Job Object.

The repaired fixture uses four distinct sync/document client/server nonce fields. DocumentContext is separate from SyncContext. End purpose5 retains the original document challenge server nonce. The final End fixture also copies its document client and completion nonces; Install purpose6 consumes those copies and hashes that End's response prefix while retaining the original SyncRequestId and active control neutral transcript. Missing or wrong-width copied metadata refuses without fallback. Tests distinguish keeping an old End from regenerating a final transfer: mutable caller control, document or completion config cannot substitute the old End's retained nonces, whereas a newly built End changes the corresponding purpose6 binding.

These are pure fixture wrappers, not verified export or End ownership tokens. They do not admit control/request/export/document consistency, current policy or semantic activation. Those contexts require separate runtime validation. Contract and wire layout remain unchanged.
